# CADD Pipeline
### *A modular command-line toolkit for automating repetitive ligand retrieval, molecular preparation, molecular docking, and post-docking interaction report generation.*

---
## Table of Contents

## Project Motivation

CADD workflows often involve repetitive use of command-line tools and Python functions for different stages of the workflow.

* **Repetitive operations:** Ligand retrieval, preparation, receptor preparation, docking, and post-docking processing involve repeated commands and file operations.
* **Multiple file formats:** The workflow requires several file conversions and molecular preparation steps between different tools.
* **Tool fragmentation:** Individual CADD tools have their own interfaces, commands, and file-format requirements, making it cumbersome to move between them.
* **Batch processing:** Performing these steps manually becomes increasingly difficult when working with large libraries of ligands or multiple protein targets.
* **Human error:** Repeated manual file handling and command execution can introduce errors, particularly during large-scale processing.

## Project Objective

Develop a lightweight CLI-based CADD toolkit to:

* Automate ligand retrieval, preparation, and batch docking.
* Standardise molecular identification and file naming as `SYNONYM_CID`.
* Integrate established CADD tools into a consistent workflow.
* Improve reproducibility of docking through user-defined random seeds.
* Improve reproducibility of protein–ligand interaction analysis through deterministic protein protonation using PDB2PQR with user-defined pH.
* Simplify batch processing while retaining human interpretation of docking and interaction results.

## Workflow

|Workflow|External Tool(s) Used|
|---| ---|
|Molecule Retrieval|PubChem PUG REST API|
|SDF Renaming|PubChem PUG REST API|
|Ligand Preparation|RDKit, Meeko|
|Protein Preparation|Meeko|
|Molecular Docking|AutoDock Vina|
|Interaction Report|PDB2PQR, PLIP, BIOVIA Discovery Studio|


## Toolkit Modules

### [`molfetch.py`](molfetch.py)

* User specifies whether they are processing CIDs or SMILES.
* User specifies the output directory for SDF files.
* Takes a `.csv`/`.tsv` file as input and lets the user select a column.
* The selected column is used to generate a list of CIDs/SMILES.
* Compounds are retrieved through the PubChem PUG REST Web API.
* Prompts the user if they wish to proceed with Molecule Renaming using the same output directory.
* Creates a separate folder for renamed compounds.
* Handles HTTP errors by retrying compounds with temporary errors such as `502` and skipping compounds with permanent errors such as `404`.
* Limits requests to 5 requests per second according to PubChem guidelines.

### [`molren.py`](molren.py)

* Uses a set of SDF files as input through `pathlib` globbing.
* Retrieves compound synonyms using the PubChem CID stored in the SDF.
* Adds the selected synonym to the `_Name` attribute of the SDF.
* Renames SDF files using the format `NAME_CID.sdf`.

### [`dockprep.py`](dockprep.py)

* Allows the user to batch-process multiple SDF files or select an individual SDF.
* Prompts the user to select an output directory or automatically generates one.
* Uses RDKit to add hydrogen atoms to ligands.
* Uses Meeko to convert `.sdf` files to `.pdbqt` files.
* Generates standardised ligand filenames using the molecule name and CID.

### [`protprep.py`](protprep.py)

* Allows the user to select a protein structure for preparation.
* Provides options for handling alternate-location residues during protein preparation.
* Uses Meeko to prepare the receptor for AutoDock Vina.
* Generates the docking box based on the selected reference ligand.
* Allows the user to specify padding for the docking box.
* Produces the prepared receptor `.pdbqt` file and corresponding docking-box configuration.
* Preserves the original protein structure separately from the prepared docking structure.

### [`dock.py`](dock.py)

* Allows the user to select a prepared protein and its ligand library for docking.
* Performs batch docking using AutoDock Vina.
* Allows the user to specify Vina exhaustiveness, number of output modes, and energy range.
* Allows the user to specify a random seed for reproducible docking.
* Uses the prepared docking-box configuration directly.
* Streams docking progress to the terminal while simultaneously saving the output to a docking log.
* Stores docking results in a dedicated output directory.

### [`analysis.py`](analysis.py)

* Processes the docked ligand poses generated by AutoDock Vina.
* Converts docked SDF poses to PDB structures for downstream interaction analysis.
* Combines individual ligand poses with the corresponding receptor structure to generate protein–ligand complexes when required.
* Uses PDB2PQR to add hydrogen atoms to the protein structure before interaction analysis.
* Allows the user to specify a pH for optional pH-dependent protonation.
* Uses the same prepared, hydrogenated protein structure for downstream interaction analysis, improving consistency between PLIP and BIOVIA Discovery Studio results.
* Uses PLIP to generate protein–ligand interaction reports for the docked poses.
* Organises interaction reports by ligand and docking pose.
* Collects pose-0 reports separately for easier manual inspection and comparison.
* Keeps interaction interpretation as a human-led step rather than automatically assigning biological significance to detected interactions.

### [`main.py`](main.py)

* Provides a single CLI interface for accessing all toolkit modules.
* Connects molecule retrieval, renaming, ligand preparation, protein preparation, docking, and interaction-report generation into a single workflow.
* Allows downstream modules to be launched directly or continued automatically from upstream preparation steps. (Eg: Protein preparation can be followed by Docking and Interaction Analysis easily)

## Key Design Decisions

* **Modular architecture:** Each workflow stage is implemented as an independent Python module, allowing individual tools to be used or combined into a larger workflow.
* **CLI-based interface:** A lightweight command-line interface was chosen to keep the toolkit simple and suitable for batch processing.
* **Established tool integration:** Existing, validated CADD and cheminformatics tools are integrated rather than recreating their functionality.
* **Standardised file organisation:** Consistent naming and dedicated output directories make large docking workflows easier to track and reproduce.
* **Reproducible docking:** User-defined random seeds allow docking runs to be repeated under the same conditions.
* **Consistent interaction analysis:** PDB2PQR provides a deterministic, pH-controlled hydrogenated protein structure as a common input for PLIP and BIOVIA Discovery Studio.
* **Human-led interpretation:** The toolkit automates preparation and reporting while leaving biological interpretation of interactions to the researcher.
